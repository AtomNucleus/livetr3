# Opt-in Gemma MTP audio experiment — 2026-10-01

Initial benchmark decision: keep MTP default-off. The bf16 assistant works with the existing audio-input,
source-first Gemma pipeline and shortens final inference, but useful-caption
cadence does not improve consistently across all pause measures. This is a
separate candidate for a user test at that stage, not an accuracy improvement.
The subsequent user-authorized promotion is recorded below.

## Promotion after user testing

The user tried the isolated MTP app, reported that this version was their
favorite, and requested a bundled friend-share app and merging PR #11. MTP is
now enabled by default with the bf16 drafter; `LIVETR3_GEMMA_MTP=0` retains the
ordinary baseline path. The self-contained distribution uses the exact target
and drafter revisions measured below. This live preference authorizes promotion;
it does not change the mixed recorded-cadence results or supply a numeric-quantity
or human Spanish score.

## Implementation and compatibility

`LIVETR3_GEMMA_MTP=1` loads
`mlx-community/gemma-4-E4B-it-assistant-bf16` with `load_drafter(kind="mtp")`
and checks `validate_drafter_compatibility` against the existing target. A block
of three contains two proposed tokens plus the target bonus; the target verifies
proposals with greedy decoding. The target model, original AST prompt, audio
preparation, six-second cap, 400 ms silence, 250 ms preview, 300 ms overlap,
source-first output, draft display policy and complete-final gates remain fixed.
No phrase-output or ordinary-ending preview-reuse experiment is inherited.

An incompatible loader or generation error disables MTP for that worker and
logs `mtp_fallback`. A failed hypothesis is discarded before a fresh ordinary
Gemma attempt. Already published progress remains provisional until the next
hypothesis replaces it; it never becomes a final solely because of fallback.
The existing larger-budget final retry remains capped at 768 tokens. There are
at most three attempts per request: one failed candidate plus the ordinary
initial attempt and bounded final retry, or an initial candidate and its larger
retry followed by ordinary fallback. Cancellation closes the generator without
retry; final scheduling and obsolete-preview cancellation stay in the serialized
worker service. Consumer callback errors propagate without disabling MTP.

The cached QAT 4-bit assistant passes architecture validation but fails during
real audio warmup on its first draft token. In mlx-vlm 0.7.3,
`gemma4_assistant.draft_block` passes the packed quantized
`model.embed_tokens.weight` directly to `masked_embedding.argmax`.
`masked_embedder._selected_logits` then indexes and reshapes it as a dense
256-wide embedding, raising:

```
ValueError: [reshape] Cannot reshape array of size 131072 into shape (1,1,4096,256).
```

This is a concrete packed-embedding compatibility failure, not evidence that
Gemma MTP cannot handle audio. The bf16 drafter completes the same audio path
without a runtime patch. The [QAT assistant model card](https://huggingface.co/mlx-community/gemma-4-E4B-it-qat-assistant-4bit)
identifies it as an MTP drafter requiring a compatible target; it is not used as
a standalone recognizer. `LIVETR3_MTP_MODEL` can select another drafter, but the
measured candidate here is bf16. No shared environment was upgraded or modified.

## Matched paced real-model comparison

Base: stable main `3b893301981c2b5e6bd0726cb6189047fc59660a`. Target:
`mlx-community/gemma-4-e4b-it-8bit`, cached revision
`4255b21bd9a9d3fc807ef7abd80373f5e3a52a73`. BF16 drafter revision:
`844e008e06ef5562bdb89428d851d0634d119dcd`. Runtime: mlx-vlm 0.7.3,
MLX 0.32.2, existing primary backend Python 3.13 environment. Cached model
configs and actual generation were checked, rather than inferring audio support
from text/image examples.

One private 51.467-second recording and its existing 133-word human English
reference were used throughout. No other independent recording with a suitable
human reference was found in the existing validation/replay artifacts. Each
condition loaded one target worker, performed startup warmup and an unscored
full paced replay, then scored a full replay before stopping that worker.
Order: baseline, MTP, MTP, baseline. Conditions used identical 20 ms frames,
two seconds of trailing silence, fixed settings, no vocabulary, no polish,
no code switching, and no early commit. The historical quiet-boundary handoff
remained enabled. Workers never overlapped, and guards checked for other
LiveTR3 model workers before and during replay.

Useful target growth uses the existing longest order-preserving word match
against each utterance's eventual complete final, omitting an unfinished last
partial word. It rejects repeated hypotheses and discarded rewrites. This is
a final-consistency proxy, not a human Spanish accuracy or physical presentation
measurement. WER ignores case/punctuation, splits contractions, and retains
boundary overlap words.

| Ordered run | Useful gap p95 / worst (s) | Gaps >2 s | First retained Spanish (s) | Last final after clip (s) | Source errors | Complete / unique finals |
| --- | --- | ---: | ---: | ---: | --- | --- |
| 1 baseline | 1.574 / 2.576 | 4 | 2.928 | 1.656 | 5/133 | 13/13 |
| 2 MTP | 1.543 / 2.675 | 3 | 2.257 | 1.301 | 5/133 | 13/13 |

| 4 baseline | 1.547 / 3.266 | 3 | 2.342 | 1.647 | 5/133 | 13/13 |

Every run had zero failures and empty/duplicate finals, 137 useful updates,
one forced cap boundary and one reused quiet prefix. All 13 final source and
Spanish strings match exactly across all four conditions. Source error
alignments also match: four substitutions, zero deletions and one overlap
insertion. This establishes no observed source regression on this clip; it
does not establish general output equivalence or improved accuracy.

MTP improved useful p95 in both pairs, but its worst gap worsened in the forward
pair and improved in the reverse pair. Gaps over two seconds improved from four
to three forward but worsened from three to four reverse. First retained Spanish
also improved forward and worsened reverse. First target characters were
0.978/0.981 s baseline and 1.113/1.168 s MTP, so faster generation did not improve
the earliest character arrival. Last-final latency improved by 0.34–0.35 s in
both orders. None of these results supports a continuous-caption claim.

## Generation versus audio preprocessing and prefill

| Ordered run | Final inference median / p95 (s) | Final generation tok/s | Verified proposed tokens | Acceptance |
| --- | --- | ---: | --- | --- |
| 1 baseline | 1.328 / 2.121 | 30.24 | — | — |
| 2 MTP | 1.060 / 1.766 | 40.16 | 617/796 | 77.51% |
| 3 MTP | 1.110 / 1.785 | 40.15 | 608/794 | 76.57% |
| 4 baseline | 1.311 / 2.138 | 30.31 | — | — |

Final inference measures worker dispatch to completion, before caption delivery;
it excludes queue time. Throughput is total final-generation tokens divided by
the sum of mlx-vlm's per-final generation durations. Acceptance includes all
scored AST attempts, including cancelled previews; startup and warmup are
excluded. Trace windows correlate worker dispatch/completion with child decode
records. Median final queue times were 0.046/0.044/0.020/0.039 s; queue p95 was
0.222/0.104/0.284/0.092 s. MTP does not remove scheduling variability.

The runtime's target prompt timer includes audio encoder processing and target
prefill; it excludes `_prepare_generation_inputs`. Median target prompt time
was 0.462/0.430/0.444/0.451 s in order. Median first streamed response was
0.469/0.435/0.449/0.456 s. These are distinct from generation throughput; the
remaining prompt work limits the end-to-end speedup.

A separate warmed same-audio ABBA probe profiled three six-second excerpts from
the beginning, middle and end of the same recording. CPU/input preprocessing
in `_prepare_generation_inputs` took 4.0–7.5 ms; audio encoder/prefill stays
inside the target prompt timer, not this CPU measurement. Complete AST call
times were 2.145–2.181 versus 1.823–1.842 s for the first excerpt,
1.893–1.904 versus 1.577–1.588 s for the middle, and 2.092–2.106 versus
1.671–1.677 s for the end. All four bilingual outputs matched exactly within
each excerpt. These fixed-input probes supplement, rather than replace, the
paced session measurements. A real MTP preview cancelled after streaming
progress returned no result; the next final remained complete, matched the
baseline excerpt, and kept MTP active.

## Native validation and isolated user test

Backend: 149 tests pass, including candidate streaming, exact-budget stop,
length retry, cancellation, bounded failure fallback, disabled/incompatible
loading, callback errors, and existing final-priority and complete-final guards.
Native: 51 tests executed, 50 passed and one optional test skipped. Release
build, Python compilation, shell syntax, diff whitespace and separate bundle
signing verification pass. Existing compiler warnings remain. A separate packaged
launcher smoke check confirmed its own bundled backend directory and
`engine_ready`, then stopped only that app/backend; this startup check does not
stand in for the real-model native replay. The initial post-launch signature
check caught generated Python bytecode inside sealed resources. The test Python
shim now uses `-B`; startup and signing were rechecked after this repair.

The isolated native candidate replayed the same file at 48 kHz through native
conversion/framing, UDS, the real worker, caption stores and SwiftUI. It sent and
received all 2,674 frames, produced 13 complete nonempty unique finals, had zero
errors/fallbacks, and scored 4/133 source errors. The missing backend overlap
insertion after native resampling reproduces the earlier native/baseline
4/133 result; it is not credited as an MTP accuracy gain. All 58 decode attempts
used MTP, including warmup and cancelled previews. Native final inference mean
was 1.167 s and p95 1.832 s; final store age from the last backend voiced frame
was mean 1.547 s and p95 2.137 s. No final-store drain followed file end.

Operator translation view character-growth callbacks had 107 updates, first
translation at 1.098 s, p95/worst gaps of 1.777/2.879 s and five gaps over two
seconds. These are view-update proxies, not final-retained words or physical
presentation times. This single native candidate run checks integration; it is
not a fresh native A/B comparison and does not establish a displayed-cadence
benefit. Both the newly created native app and external backend were stopped.

`script/build_mtp_candidate.sh` builds a distinct signed
`dist/LiveTR3-gemma-mtp.app` with its own bundle identifier and a Python shim to
the existing environment. Set `LIVETR3_MTP_PYTHON` to that environment's Python
when the worktree has no local `.venv`. It does not stop or launch the normal app.
`script/launch_mtp_candidate.sh mtp` selects the candidate;
`script/launch_mtp_candidate.sh baseline` selects ordinary decoding in the same
bundle. Each launch has an isolated socket, archive and trace, refuses an active
known model worker, and does not start microphone capture automatically.

The identified idle phrase experiment app/backend were retired after checking
ownership. Its historical evidence, branches and archives were preserved.
Other existing backends and unrelated apps were preserved. The stable normal
bundle and primary checkout were not replaced, merged or deployed.

No live microphone or physical projector test was performed. This recording
has no explicit numeric quantities, so numeric-quantity acoustic validation is
unavailable. No human Spanish reference/scoring is available. The benchmark recommendation was to keep the candidate default-off pending
live user preference. The promotion above records the user choosing this
version; the unavailable acoustic and Spanish-scoring evidence remains so.

## Reproduction and private evidence

Use an existing compatible backend Python; set `PYTHONPATH=app/backend` for
`script/gemma_mtp_replay.py`. Supply `--audio`, `--reference`, `--output` and
`--mode baseline|mtp`; run baseline/MTP/MTP/baseline into separate ignored
output directories. Each command warms and stops its own worker.
`script/gemma_mtp_summary.py` summarizes those directories without printing
captions. `script/gemma_mtp_probe.py --audio ... --output ...` performs the
fixed-input/profile/cancellation check. Run model experiments serially.

All private data remains local under `dist/logs/mtp/`: `01-baseline`, `02-mtp`,
`03-mtp`, `04-baseline`, `profile`, `native-candidate`, numerical `summary.json`,
package/test logs, runtime source hashes and both drafter compatibility probes.
The audio, reference, captions, source error alignments and native archives are
not committed. Native replay accepts `--audio` so a worktree can use a private
fixture without copying it into tracked source.
